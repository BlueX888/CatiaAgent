## 模块拆分：三个可独立成项的项目

同一个项目可以拆成"工具层 / 运行时 / 评测"三个条目，各自回答不同问题，指标不重复。

### 拆分原则

1. **一个项目一个中心能力**：MCP Server 讲工具与执行，建模智能体讲规划与上下文，评测基准讲如何证明成功。
2. **指标不重复**：同一个数字只出现一次，避免面试官发现三个项目在讲同一件事。
3. **角色与时间一致**：都写"独立开发 / 主导"，时间线对齐。
4. **每个都能独立讲 10 分钟**：拆完要在面试里各自站得住。

## 一、为什么这个项目适合 Agent Harness 岗位

Agent Harness 的核心不是"调模型"，而是**把模型变成能可靠做事的系统**：工具怎么定义、上下文怎么给、权限怎么收、失败怎么恢复、结果怎么验。

这个项目是**航空装备设计场景的执行型智能体**：服务航空主机厂的 CATIA 参数化改型与图纸建模，不是通用聊天助手。它同时是一个"困难模式"的 harness 样本：

- **没有可靠 API**：CATIA 只有桌面 COM，不是幂等 HTTP 接口；
- **操作不可逆**：改错一个参数，模型文件可能已经脏了；
- **结果不能靠模型自述**：几何对不对，必须独立读回和材料比对；
- **执行环境会卡死**：CATIA 弹窗、COM 崩溃、超时都是常态；
- **上下文极重**：完整模型快照是 MB 级，必须压缩成模型能用的任务上下文。

在这样的环境里跑通"规划 → 工具调用 → 校验 → 恢复 → 交付"，比在理想 API 上做 demo 更能说明 harness 工程能力。

## 六、面试必答（Harness 版）

1. **怎么设计一个"模型能安全调用"的工具？**
   - schema 明确输入类型、单位、必填项，拒绝隐式补全；
   - 读操作和写操作分开，写操作必须可回滚；
   - 返回结构化结果：`ok/code/operation_id/effects/diagnostics/recovery`，模型能据此决定重试、澄清还是停止；
   - 写后读回，不把"调用成功"当成"结果正确"。

2. **上下文怎么管？**
   - 完整模型快照是 MB 级，不能直接塞进上下文；
   - 按任务抽取约 4.5KB 的任务上下文：对象标识、结构语义、特征依赖、历史修改；
   - 意图编译把自然语言先变成结构化计划，减少模型在长上下文里反复推理；
   - 效果：35/35 正确、耗时 −50%、P95 −59%、token −20%。

3. **不可逆操作怎么防？**
   - 所有写操作在服务器持有的工作副本上进行，原件只读；
   - 每步记录 effects，失败按协议回滚；
   - 缺单位、对象不明、约束冲突时澄清闸门直接拦截，不让模型自行补条件；
   - 结果不确定时禁止重试，先检查模型状态。

4. **怎么判断 Agent 真的成功了？**
   - 不采信模型自述，也不只采信工具返回；
   - 双证据链：CATIA 新进程重开（体积、包围盒、圆柱面、孔位孔径、参数、公式）+ OCCT 非破坏性 common/双向 cut 材料比对（10 档 fuzzy、冻结容差）；
   - 双 PASS 才算交付，否则只出诊断；历史假成功声明为 0。

5. **执行环境不稳定怎么办？**
   - CATIA 是 STA COM 服务器，所有调用绑定单一持久线程串行执行；
   - 客户端取消不会中断已入队/执行中的写操作，避免"以为取消了其实改了一半"；
   - 超时、弹窗、COM 异常统一转成可恢复错误；
   - 进程崩溃后先检查模型状态，不盲目重放。

6. **为什么用 MCP？换模型/换平台怎么办？**
   - MCP 提供标准工具发现、schema、调用和错误语义，执行端可被任意 MCP 客户端复用；
   - 项目已实际经历 AgentCPM → PilotDeck 迁移，CAD 侧零改动，证明了解耦价值；
   - 如果只是单机 demo，会直接写本地 HTTP 执行端，不必上 MCP。

### 面向成飞的追加问题

7. **军工内网怎么部署？**
   - 执行端部署在 CATIA 同机，编排层部署在内网服务器；不依赖公网；
   - 跨机只传工具调用参数与校验结果，图纸、模型、STEP 不出内网；
   - 模型层与执行层解耦，可替换为内网部署的模型服务。

8. **怎么保证不误改、可追溯？**
   - 工作副本 + 原件只读 + 失败回滚；
   - 每次调用有 operation_id、effects、diagnostics，交付附验收 JSON 与变更报告；
   - 双证据链独立判定，模型自述不算数。

9. **会不会替代工程师？**
   - 定位是"减少重复改型、图纸重建、孔系创建"，不是替代设计决策；
   - 歧义、约束冲突会澄清或拒绝，最终交付仍由工程师复核；
   - 长期价值是把资深工程师的改型经验沉淀成可复用规则和案例。

10. **和现有 CATIA / PDM 流程怎么配合？**
    - 走 CATIA 原生 COM 与原生特征树，产出标准 CATPart，不引入私有格式；
    - 文件落盘位置、命名、报告格式可配置；
    - 不改变工程师日常操作，Agent 在后台执行，避免切换工作流。

## 八、诚实红线（务必遵守）

1. **PilotDeck 不是本项目开发的。** 它是清华 THUNLP / OpenBMB 的开源 Agent 平台。
   正确写法："基于 PilotDeck 搭建 CATIA 产品包 / 完成插件迁移"。
2. **MCP Server 可以写"主导开发并开源"。** 仓库 `daiemon12/catia-v5-mcp-server`
   的提交历史包含本项目新增的 editing / drawing / text-to-cad 工具链。
