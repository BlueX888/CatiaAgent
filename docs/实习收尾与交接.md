## 四、能力边界（必须如实交接）

### 已支持

- 已保存的**单实体参数化** `.CATPart` 改型：长度、宽度、厚度、孔径、孔边距等驱动参数；
- 单零件 PDF 工程图建模：平面板件、圆环、闭合轮廓、组合特征；
- 孔/凸台区分、侧面孔、孔组、草图坐标与模型坐标转换；
- 工作副本、原件保护、失败回滚、落盘重开验证。

### 未支持 / 未验证

- 改型新增特征、装配、多实体联动、自由曲面/GSD、折弯/曲面钣金、无参数导入实体；
- 复杂曲面圆角、侧向多轴特征——NIST 剩余 14 例的主要阻塞；
- 扫描图无尺寸逆向、模糊指代（未实现用户选中对象直接定位）；
- **Win7 / Python 3.8 只完成架构设计，未在客户实机跑通**；
- 长会话完整历史分页、CATIA 构建卡片/三维预览（PilotDeck 迁移后未移植）；
- 无人工建模基线，不能宣称节省工时或效率倍数。

### 已知环境坑

- CATIA 是 STA COM 服务器，所有调用必须串行；
- pywin32 `gen_py` 缓存过期会导致方法"消失"，清理缓存可恢复；
- 工具调用期间切换 CATIA 活动文档会导致目标错位；
- 旧版本 CATIA 打不开新版本保存的文件；
- 模态弹窗会阻塞 worker，只能人工关闭或重启 CNEXT。

## 六、简历与面试的闭环口径

### 简历三句话

> 实习期内完成航空工业建模智能体从 0 到 1 的端到端闭环：把 100+ CATIA 操作封装为 MCP 工具，打通自然语言/PDF 图纸到参数化模型的规划、执行、校验与交付；建立 NIST 17 例基准与双证据链验收，3 例达到严格完成标准，历史假成功声明为 0；完成 AgentCPM → PilotDeck 迁移并交付可复现的测试与交接文档。

### 面试被问"为什么只做到这里"

> 实习周期结束，项目按阶段交付收口。我们把能做的做成了可复现的闭环，把做不到的定位到了具体能力边界（复杂曲面圆角、侧向多轴特征、Win7 运行时），并留下了基准、验收管线和交接文档，下一阶段可以直接接着做，不需要重新摸底。

要点：

- 说"阶段交付"，不说"没做完"；
- 说"边界已定位"，不说"能力不够"；
- 用数字证明闭环，不用形容词。

### 不要写

- "已在客户现场稳定运行"（Win7 未实机验证）；
- "通过 NIST 17 例"（是 3/17 严格完成）；
- "替代工程师 / 节省 X 小时"（无人工基线）；
- "开发了 PilotDeck"（是基座，不是本项目产出）。
