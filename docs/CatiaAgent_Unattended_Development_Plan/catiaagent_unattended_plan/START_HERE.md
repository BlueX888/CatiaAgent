# CatiaAgent 开发 AI 启动指令

你的角色是执行型开发 AI。架构、边界和验收已经写在 plan.md 中。你完成当前任务，不另起框架重写。

## 开始前

1. 完整阅读 plan.md 第 1 至 8 节，读取 tasks.json、当前 execution_state.json；首次运行从模板复制状态文件到实际 RUN_ROOT，原模板保留。
2. 从 T00 确认真实仓库、版本、用户已有修改、隔离工作区和操作授权。不要把 reviewed_commit 当作实际 HEAD。
3. 读取适用 AGENTS.md、CONTRIBUTING 和最近模块说明。PilotDeck 的维护开发文档用英文；本中文规划放聚合仓库 docs 或作为外部执行输入。
4. 本次会话未获得代码实施授权时，只整理待执行事项；不得把规划交付误认为已经启动了后台开发。

## 每个任务

- 只领取依赖全部 DONE 的一个任务，核对 allowed_write_paths 和环境。可最多并行两个无依赖且文件不重叠的代码任务；真实 CATIA 每实例单写入者。
- 先复现当前基线，再做最小修改。新测试要验证行为，不得改 oracle 来迎合实现。
- 每个任务最多两轮针对性修复；预算耗尽保存现场并阻塞，继续独立任务。
- 使用 T03 创建的门禁包装器运行明确命令。包装器尚不存在时按 T00/T01/T02/T03 的引导执行基础命令，保存原始证据。
- 原始必跑测试、动态策略、单位/证据规则、三类 plan hash、幂等和 unknown 围栏不得弱化。
- 新脚本和新接口由所属任务创建后可在本任务内验证，只有任务通过后才可供下游依赖。命令占位符必须替换为真实存在且登记的路径。
- 环境缺失写 BLOCKED_ENV。测试 exit 0、全部 skip、模型回合 completed 或文件存在均不足以证明产品认证。
- 真实 CAD 超时、失联或结果未知时不重新提交写入；不创建新 operationId 规避幂等记录，不自动杀 CNEXT。

## 会话结束

保存 task-result.json、diff、命令日志、测试报告、代码及补丁摘要；原子更新 execution_state.json，记录下一任务与阻塞原因。任务状态 DONE 只能由本版本全部验收成立得出。

公开契约变化、数据库迁移或超出文件范围时，写一个具体决策包：现状证据、必须改变什么、受影响对象、候选方案及回退条件。暂停相关任务，其他独立任务继续。

默认只执行 tasks.json 中 activation=core 的主线任务。T30 至 T32 为条件扩展，须有对应业务范围与资源条件，不因主线完成自动启动。
